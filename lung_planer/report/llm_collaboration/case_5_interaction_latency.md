# 案例 5：拖动结束至完整规划结果的交互延迟

## 用户提示词

我想优化“拖动结束至完整规划结果就绪”的交互延迟。请按板端日志把耗时拆成三段：规划数值任务、内部切面处理、外露显示面生成，找出主要瓶颈并给出优化顺序。

建议先优化重复的 BVH 构建、数组分配和批量几何查询，再评估 PL 是否能介入。不要因为项目用了 FPGA 就默认所有瓶颈都应迁移到 PL：现有 PL 负责规划计算，不会自动提高 Qt Quick 3D/Mali 的绘制帧率；只有当 CPU 几何准备是瓶颈时，PL 才可能有帮助。切面面积依赖内部切面生成，不能把数值就绪时间简化成单一的 1.15 秒。

请用同一病例的板端记录报告各阶段耗时及占比，明确 2 秒是挑战目标，须在保持算法和显示质量的前提下做实测优化。交互性能要测到“用户操作完成、最终结果就绪”的完整路径，区分计算、几何构造和 GPU 绘制，并按最大耗时占比确定优化顺序。

## 模型回答与行动

按板端日志，把耗时拆成三段：规划数值任务、内部切面处理、外露显示面生成。指出外露显示面生成是主要瓶颈。

建议的顺序：先优化重复的 BVH 构建、数组分配和批量几何查询，再评估 PL 是否能介入。

## 自我纠错轨迹

- 模型明确修正了「PL 可能直接提速」的泛化预期：现有 PL 负责规划计算，不会自动提高 Qt Quick 3D/Mali 的绘制帧率；只有当 CPU 几何准备是瓶颈时，PL 才可能有帮助。
- 并说明切面面积依赖内部切面生成，不能把数值就绪的时间简化成单一的 1.15 秒。

## 验证证据与结果

同一病例的板端记录：

| 阶段           | 耗时                          |
| ------------ | --------------------------- |
| 核心数值与完整校验    | 约 1.15 秒                    |
| 内部切面及相关处理    | 约 1.15 秒                    |
| 完整规划（以上两段合计） | 约 2.31 秒                    |
| 外露显示面生成      | 约 12.85–13.81 秒，占两段合计的约 85% |

因此 2 秒是挑战目标，须先在保持算法和显示质量的前提下做实测优化。

## 可复用经验

- 交互性能要测到「用户操作完成、最终结果就绪」的完整路径。
- 区分计算、几何构造和 GPU 绘制。
- 按最大耗时占比确定优化顺序，不因为项目用了 FPGA 就默认所有瓶颈都应迁移到 PL。
