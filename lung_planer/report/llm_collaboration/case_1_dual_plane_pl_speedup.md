# 案例 1：双平面楔形 PL 加速

## 用户提示词

请基于现有双平面楔形 PL 加速工程，完成一轮 RTL 与 PS 侧协同优化，目标是把两个病例的冷启动 P50 从约 40 秒降低到 20 秒以内。

RTL 侧重点实现 FP64 连续发射与算术单元共享；PS 侧重点完成向量化、初始化依赖精简和候选调度准备。随后请完成综合、布线、部署、全候选验收，并做冷启动 A/B 对比。

验收和报告中请给出：两病例冷启动 P50、每例候选数与误差、`cpu_fallback_count`、时序结果、资源占用；同时建立不重叠的端到端时间预算，区分启动、核等待与核外时间，确认病例准备与 PL 初始化是否重叠，不能重复相加。

请把每次 RTL/PS 改动绑定到可归因的实测收益；对实测收益过小的原型要淘汰并说明依据。若最终未达到 20 秒目标，必须明确写出“尚未达到 20 秒”，不得把优化目标写成已达成成果。最终报告需同时覆盖性能、资源、时序、正确性、CPU 回退情况和未达成目标。

## 模型回答与行动

根据关键路径预算，并行推进两部分工作：

- **RTL：** FP64 连续发射与算术单元共享。
- **PS 侧：** 准备向量化、初始化依赖精简和候选调度。

随后完成综合、布线、部署、全候选验收和冷启动 A/B 对比。

## 自我纠错轨迹

- 早期把部分方向作为候选方案。
- 随后依据各阶段计时，拆出启动、核等待与核外时间，确认病例准备与 PL 初始化是重叠的，不能重复相加。
- 最终明确写出「尚未达到 20 秒」，并淘汰了实测收益仅约 0.03 秒的原型，没有把目标写成成果。

## 验证证据与结果

| 项目         | 结果                                    |
| ---------- | ------------------------------------- |
| 两病例冷启动 P50 | 40.382 / 41.176 秒降至 20.929 / 21.552 秒 |
| 候选数与误差     | 每例 780 个候选，误差满足 1e-5                  |
| CPU 回退     | `cpu_fallback_count=0`                |
| 时序         | 100 MHz，WNS +0.460 ns                 |
| 资源         | CLB 14521 / 14640                     |

**对应的位流版本。** 上表的耗时、时序和资源都来自优化过程中的中间版本（2026-10-29 的 DAG 流水版），
它还带有第二个双平面核，CLB 占用接近 99%。提交的最终位流在此之后精简为单核，指标是 WNS +0.416 ns、
CLB 92.40%、LUT 56.11%（见根目录 README），**不是**上表这一版，两组数字不能互相替换。
最终位流上的 PL 与 PS 对比见根目录 README 的“性能对比”一节：同一块板上，780 个候选的双平面网格核，
PL 9.06 s，PS 77.7 s，约 8.6×。端到端冷启动时间没有在最终位流上重测。

## 可复用经验

- 建立不重叠的端到端时间预算。
- 把每次 RTL/PS 改动绑定到可归因的实测。
- 同时报告性能、资源、时序、正确性与未达成的目标。
- 优化目标不能替代验收结果。
