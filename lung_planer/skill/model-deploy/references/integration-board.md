# 集成、实现与板端一致性验收

适用：算子都已通过算子级验证，开始接进顶层、出 bitstream、上板验收。

## 1. 系统分层

| 层 | 内容 | 语言 |
|---|---|---|
| 算子层 | 卷积、池化、逐元素、行缓冲等数据通路 | SpinalHDL 或 SV |
| 调度/控制层 | 命令解析、层调度、地址生成、状态机 | SV |
| 存储层 | 片上缓存、DDR 读写仲裁、跨时钟域 | SV + 官方 IP（MIG/XPM） |
| 接口层 | PYNQ（AXI-Lite + AXI DMA）或外部链路（以太网/UART/PCIe） | Verilog/SV |
| 顶层 | 例化与连线 | Verilog（BD 场景须 Verilog-2001） |

**一套可配置阵列按层复用**，不同任务只换权重、输出头与层配置：资源不随任务数增长，代价是配置面变宽、验证矩阵变大（每种配置都要有算子级向量）。

调度命令格式、阵列参数（P 并行度、lane 数）、片上缓存大小在动手前写成接口文档，并给出每层的周期估算公式，后续与实测周期对照。

## 2. 资源与时序预算

- 先估算：MAC 数 → DSP；权重 + 特征图双缓冲 → BRAM/URAM；单项不超过 85%。
- 每轮实现后：`python <skill>/fpga/scripts/qor_check.py --timing ... --util ... --history qor_history.csv --tag <round>`。
- 资源突变、WNS 为负按 `../../fpga/references/timing-closure.md` 处理；生成器类 RTL 的映射属性丢失是本路线最常见的根因。
- 构建脚本带 WNS/WHS 门禁（见 `../../fpga/references/vivado-tools.md` 第 2 节），不过门禁不出 bitstream。

## 3. 两条上板路径

| 路径 | 适用 | 数据通路 | 参考 |
|---|---|---|---|
| A. 板内 PYNQ | Zynq/Kria 板，加速器在同一芯片 PL | AXI-Lite 控制 + AXI DMA 或 PL 主口访问 DDR | `../../pynq/` |
| B. 外部链路 | 纯 FPGA 板，主机经网口/串口/PCIe 驱动 | 自定义协议 | 本页第 4 节 |

## 4. 外部链路协议的设计要点

协议是主机与板卡之间的契约，与数值契约同等重要。

| 要点 | 做法 |
|---|---|
| 版本化 | 每种消息/文件带 `format` 字段（如 `xxx-job-v2`），板端拒绝不认识的版本 |
| 哈希贯穿 | 输入、调度表、权重的 SHA256 出现在 job、status、result 每一份交接文件里，任一环不一致即判失败 |
| 传输 ID | 每次传输一个 `transfer_id`，重试必须换新 ID |
| 布局显式 | `layout`、`byte_order`、`row_stride`、`plane_stride` 显式写出；有 stride 意味着有对齐填充 |
| 完整性 | 每帧 CRC；以太网 FCS 与 `zlib.crc32` 位序不同（`zlib.crc32 == bitreverse32(~crc32_d8)`），主机侧比对时注意 |
| 状态遥测 | 状态查询返回已完成命令数、引擎/调度器状态、读写空闲、在途请求、阻塞周期计数，卡住时能看出卡在哪一级 |
| 无进展检测 | `no_progress_seconds` 超过阈值即判失败，保留最后一份状态，不无限等待 |
| 重试 | 先读最后状态判断卡点，再决定重传还是重启计算；保留第一次失败的目录 |

协议解析 RTL 的典型缺陷（本项目以太网仿真中实际发现）：进入空闲时误清字节计数导致整帧错位一字节；长度字段只在最后一拍有效却被提前采样；发送缓存读出多走一拍；位图的字节内位序反了。这些都应在协议级 TB 里用变长报文 + 队列比对覆盖。

## 5. 板端一致性验收

### 5.1 逐位一致（底线）

板端输出与 PC 运行**同一套冻结整数网络**的输出做 SHA256 比对；不一致时用 `scripts/compare_tensors.py` 定位首个差异的坐标。

能做到逐位一致的前提（缺一不可）：

1. PC 侧跑的是冻结整数图，不是浮点模型；
2. 两边使用同一份权重与输入文件（哈希相同）；
3. 字节序、layout、通道顺序完全一致；
4. 整数图本身在 CPU 与 GPU 上逐位一致（训练侧已验证）。

只比最终输出可能掩盖中间层错误被后续层抵消，调试阶段要能回读中间节点逐层比对。

### 5.2 任务指标（面向应用）

逐位一致证明实现正确；任务指标（Dice、IoU、准确率、mAP）证明量化后的模型仍可用。比较对象是同一输入下的 FP32 模型与整数图，验收阈值事先写定（例：每类 Dice 下降不超过 2 个百分点）。两类结论都要给。

### 5.3 验收记录

| 项 | 要求 |
|---|---|
| 比对对象 | 板端输出 vs PC 整数图输出 |
| 关联哈希 | 输入、权重/调度表、bitstream、输出 |
| 覆盖范围 | 写明几例、什么尺寸；不用单例结论代表全量 |
| 未覆盖 | 未测的尺寸、通道数、边界情形 |
| 性能 | 端到端时间与各阶段时间，注明频率、bitstream 哈希、重复次数；与基线（CPU/GPU）同口径对比 |

## 6. 报告分层

1. 仿真层：算子功能与 Golden 一致；
2. 实现层：时序收敛、资源占比；
3. 板端层：实际跑通、状态与遥测正常；
4. 一致性层：板端输出与 PC 参考逐位一致，任务指标达标。

任何一层缺失就写明缺失，不用下一层的结论代替。生成了新 bitstream 但未重新上板，要写明上板证据对应的是哪个 bitstream。
